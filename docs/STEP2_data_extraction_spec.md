# Step 2 — Data Extraction & Synthetic Ingestion Spec

## Scope
This document defines the Step 2 synthetic data generation and ingestion pipeline for the team-week panel:

- **Topic:** AI-assisted coding adoption and junior output concentration
- **Unit of observation (analysis):** team-week
- **Synthetic cycle:** yes (no external production data pulled in this step)
- **Pipeline script:** `scripts/step2_synthetic_pipeline.py`

## Pipeline goals
1. Produce reproducible synthetic raw records at the **team-role-week** level.
2. Ingest raw records into a clean **team-week analytic panel**.
3. Save machine-readable artifacts and metadata in `outputs/`.
4. Lock definitions now so later steps do not drift silently.

## Input design (synthetic DGP components)
The script creates three conceptual layers:

1. **Team baseline layer**
   - `team_id`
   - `team_size`
   - `baseline_complexity`
   - `baseline_junior_mix`
   - `manager_quality`
   - `adoption_week` (staggered for adopters, missing for never adopters)

2. **Team-week latent process layer**
   - `treated` indicator based on whether `week_index >= adoption_week`
   - latent junior share process (logistic transform)
   - latent output volume process (Poisson intensity)

3. **Role split layer (raw extract)**
   - role = `junior` or `senior`
   - role-level output counts by week:
     - `merged_prs`
     - `completed_tickets`
     - `role_output`

## Output artifacts
Generated by running the Step 2 script:

- `outputs/step2_synthetic_team_role_week.csv`
  - raw synthetic extract (team-role-week rows)
- `outputs/step2_team_week_panel.csv`
  - ingested analysis panel (team-week rows)
- `outputs/step2_data_dictionary.csv`
  - variable list, types, and definitions
- `outputs/step2_generation_metadata.json`
  - seed/config and quick diagnostics

## Ingestion and construction rules
Raw-to-panel transformation:

1. Aggregate role rows to team-week totals:
   - `total_merged_prs`
   - `total_completed_tickets`
   - `total_output`

2. Join junior-only role rows:
   - `junior_merged_prs`
   - `junior_completed_tickets`
   - `junior_output`

3. Compute shares:
   - `junior_merged_pr_share = junior_merged_prs / total_merged_prs`
   - `junior_ticket_share = junior_completed_tickets / total_completed_tickets`
   - `junior_output_share = junior_output / total_output`

4. Construct treatment timing fields:
   - `event_time = week_index - adoption_week`
   - `post_period = 1{week_index >= adoption_week}` for adopters, else 0

5. Mark analysis sample:
   - `analysis_sample = 1{total_output >= 10 and junior_output_share observed}`

## Reproducibility lock
The script is deterministic conditional on fixed parameters:

- default seed: `20260309`
- default teams: `48`
- default weeks: `30`
- adoption share target: `0.70` (realized share may vary slightly)

Run command:

```bash
python scripts/step2_synthetic_pipeline.py --seed 20260309 --n-teams 48 --n-weeks 30
```

## Immediate data-quality checks for Step 2
- No missing `team_id`, `week_index`, or role counts in raw extract.
- Exactly two roles per team-week in raw extract.
- Panel row count equals `n_teams * n_weeks`.
- Shares in `[0, 1]`.
- `event_time` only populated for adopter teams.

These checks are intended for quick validation before Step 3 modeling.
